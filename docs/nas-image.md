# 自有 NAS 镜像

镜像地址：`ghcr.io/xhui999w/go-emby2`。当前构建目标为绿联 DXP4800 的 Linux amd64。

`Dockerfile.nas` 保留已安装的上游 2026.11.17-160707 运行时，并应用 `runtime-patches/web/` 中维护的前端修复。它是自有派生镜像，并不表示已经取得该运行时对应的完整后端源码。仓库原有 `Dockerfile` 是公开源码的构建入口，与 NAS 运行时版本不同。

## 构建与版本

修改运行时补丁并推送 main 后，`Build NAS image` 工作流构建镜像，发布 `latest` 和不可混淆的 `sha-提交前12位` 标签。生产部署应使用固定提交标签。工作流同时保留可直接加载的 Docker 镜像归档，避免 NAS 拉取私有 GHCR 包时需要额外凭据。

补丁构建严格校验上游可执行文件 SHA-256、资源唯一性、替换长度和 ELF 数据段位置。仅替换两个内嵌 JavaScript 文件和构建版本常量的数据，保留程序长度及可执行段。构建版本变更使浏览器重新获取前端资源，避免继续使用旧缓存。更换上游版本时必须重新核对指纹、资源和行为；校验不通过即停止构建。

构建还会将镜像归档附加到候选 GitHub Release，供不具备 GHCR 包读取权限的部署环境下载。候选版本先完成 NAS 验证，再正式部署；生产环境始终使用固定提交镜像标签。

## 本次行为

- 批量添加支持直接勾选多个分类目录，跨页和进出目录保留选择，每个分类目录创建一个媒体库。
- 普通添加使用所选目录本身作为媒体库路径，后台递归扫描整个目录；不再把已显示的下一层目录当作完整导入范围。
- 保留单独的穿透识别模式，用于需要按媒体边界发现目录的场景。
- 使用清晰的原生勾选控件；部分提交失败后，成功目录不会再次提交。

## NAS 更新

更新前保存实际 Compose 配置、应用数据及数据库逻辑备份，并记录旧镜像 ID。只替换应用和 schema-prepare 的镜像；保持原项目名、数据库、bootstrap 卷、媒体挂载、端口和网络设置。先用临时端口验证修复镜像，再更新生产服务。回滚使用保存的配置和旧镜像；本补丁不更改数据库结构。

`scripts/deploy-nas.py --project-dir 部署目录 --image 固定镜像标签` 在镜像已经加载后执行这些步骤：备份配置和数据库，在隔离数据库及测试目录中验证资源哈希和跨 256 项目录分页的 300 部电影、300 集电视剧扫描，再仅重建应用容器并验证健康状态。支持 `--stage-only`，验证失败会在更新前停止；生产切换验证失败会恢复旧镜像。

后续如果需要修改当前运行时的新后端功能，应先补齐相应源码实现及兼容性验证，再决定是否切换到完整源码构建镜像。
